## 🌟 نظرة عامة

**محفظتي المالية** تطبيق ويب خفيف ومستقل بالكامل لإدارة الشؤون المالية الشخصية. يعمل مباشرة من المتصفح بدون أي سيرفر خلفي، ويعتمد على **Supabase** كقاعدة بيانات سحابية مجانية — بحيث تكون بياناتك محفوظة في مشروعك الخاص ولا يراها أحد غيرك.

> **لماذا هذا المشروع؟**
> معظم تطبيقات إدارة المال إما مدفوعة، أو تسرق بياناتك، أو معقّدة. هذا المشروع يمنحك تحكمًا كاملاً: الكود مفتوح، البيانات في حسابك، والتشغيل مجاني للأبد.

## 🛠 التقنيات المستخدمة

- **الواجهة**: HTML5 + CSS3 + Vanilla JavaScript (بدون أي framework)
- **قاعدة البيانات**: PostgreSQL عبر [Supabase](https://supabase.com)
- **المصادقة**: Supabase Auth (Email + Password)
- **أسعار الصرف**: [open.er-api.com](https://open.er-api.com) — مجاني بدون مفتاح
- **أسعار المعادن**: [GoldAPI.io](https://www.goldapi.io) — مفتاح مجاني اختياري
- **الاستضافة**: أي استضافة ثابتة (GitHub Pages / Netlify / Vercel / محليًا)

## 🚀 الإعداد الكامل خطوة بخطوة

### الخطوة 1: إنشاء مشروع Supabase

1. اذهب إلى [supabase.com](https://supabase.com) واضغط **Start your project**.
2. سجّل بحساب GitHub أو Google أو بالبريد.
3. من لوحة التحكم، اضغط **New project** واملأ:
   - **Name**: اسم المشروع (مثلًا `personal-finance`)
   - **Database Password**: كلمة مرور قوية — **احفظها في مكان آمن**
   - **Region**: اختر منطقة قريبة جغرافيًا (مثلًا `Frankfurt` أو `Bahrain` للشرق الأوسط)
   - **Pricing Plan**: `Free`
4. اضغط **Create new project** وانتظر دقيقة أو اثنتين حتى يجهز.

---

### الخطوة 2: تشغيل سكريبت قاعدة البيانات

1. من القائمة الجانبية داخل مشروعك، اختر **SQL Editor**.
2. اضغط **+ New query**.
3. افتح ملف `schema.sql` من هذا المستودع، وانسخ **كل محتواه**.
4. الصقه في محرر الاستعلام.
5. اضغط **Run** (أو `Ctrl + Enter`).
6. انتظر حتى تظهر رسالة `Success. No rows returned` — معناه أن كل الجداول والفهارس والسياسات أُنشئت.

**للتحقق:**
- اذهب إلى **Table Editor** — يجب أن ترى 15 جدولًا.
- اذهب إلى **Authentication → Policies** — يجب أن ترى سياسات على كل جدول.

> ✅ `schema.sql` **آمن لإعادة التشغيل** في أي وقت — لن يحذف بياناتك. يمكنك إعادة تشغيله عند إضافة جداول جديدة مستقبلًا.

---

### الخطوة 3: تفعيل تسجيل الدخول بالبريد

1. من القائمة الجانبية: **Authentication → Providers**.
2. تأكد أن **Email** مفعّل (عادةً مفعّل افتراضيًا).
3. **اختياري**: لتسجيل دخول فوري بدون تأكيد بريد:
   - اذهب إلى **Authentication → Providers → Email**.
   - عطّل خيار **Confirm email**.
   - اضغط **Save**.
   
   > مناسب للاستخدام الشخصي. لو تركت التأكيد مفعّلًا، ستحتاج فتح رابط التأكيد المُرسل لبريدك قبل أول تسجيل دخول.

---

### الخطوة 4: الحصول على بيانات الاتصال

1. من القائمة الجانبية: **Project Settings → API**.
2. انسخ القيمتين التاليتين واحفظهما مؤقتًا:
   - **Project URL**: مثل `https://xxxxx.supabase.co`
   - **anon public key**: مفتاح طويل يبدأ بـ `eyJ...`

> ⚠️ **لا تنسخ** `service_role key` أبدًا — هذا المفتاح يتجاوز كل سياسات الأمان ولا يجب أن يظهر في أي واجهة.

---

### الخطوة 5: فتح التطبيق وتسجيل الحساب

**خيار A — محليًا:**
- افتح ملف `index.html` مباشرة في المتصفح (انقر عليه نقرًا مزدوجًا).

**خيار B — على الإنترنت:**
- انشر الملفات على GitHub Pages (انظر [القسم التالي](#-النشر-على-github-pages)).

**ثم:**
1. في أول تشغيل، ستظهر شاشة **الاتصال بقاعدة بياناتك**.
2. الصق **Project URL** و **anon public key** اللذين نسختهما.
3. اضغط **اتصال**.
4. اعمل **Sign up** جديدًا:
   - البريد الإلكتروني
   - اسم المستخدم
   - كلمة المرور
5. سجّل دخولك — **التطبيق جاهز الآن**، وكل بياناتك ستُحفظ في مشروع Supabase الخاص بك.

> 💡 بيانات الاتصال تُحفظ محليًا في متصفحك (`localStorage`)، فلا تحتاج إدخالها كل مرة.

## 🌍 النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub (عام أو خاص).
2. ارفع الملفات: `index.html`, `style.css`, `app.js` (و`README.md` و`schema.sql` اختياريًا).
3. اذهب إلى **Settings → Pages**.
4. تحت **Source**:
   - **Branch**: اختر `main` (أو الفرع الذي رفعت عليه).
   - **Folder**: اختر `/ (root)`.
5. اضغط **Save**.
6. بعد دقيقة، سيظهر الرابط:
   ```
   https://<username>.github.io/<repo-name>/
   ```
7. افتح الرابط وأدخل بيانات Supabase كما في [الخطوة 5](#الخطوة-5-فتح-التطبيق-وتسجيل-الحساب).

**بدائل ممتازة:**
- [Netlify](https://netlify.com) — اسحب المجلد وانشره فورًا
- [Vercel](https://vercel.com) — اربط المستودع وانشر تلقائيًا
- [Cloudflare Pages](https://pages.cloudflare.com) — سريع ومجاني

## 🔄 التحديث التلقائي للأسعار

### أسعار الصرف
- **يدويًا**: من صفحة **تحديث الأسعار** داخل التطبيق.
- **تلقائيًا**: يوميًا عند أول فتح للتطبيق، من [open.er-api.com](https://open.er-api.com) — مجاني بدون مفتاح.

  2. افتح التطبيق → **الإعدادات**.
  3. الصق المفتاح واحفظ.
  4. سيتم تحديث أسعار المعادن المملوكة فقط (توفيرًا لاستهلاك الحصة المجانية).

## 🔐 الأمان

| الطبقة | آلية الحماية |
|---|---|
| **المصادقة** | Supabase Auth (بريد + كلمة مرور) |
| **التفويض** | Row Level Security (RLS) على كل الجداول |
| **السياسات** | `USING (true)` لدور `authenticated` فقط |
| **anon key** | آمن للنشر في المتصفح (مصمم لهذا الغرض) |
| **service_role key** | ⚠️ لا يُنشر أبدًا في الواجهة |

> **ملاحظة مهمة:** سياسات RLS الحالية تسمح لأي مستخدم مسجّل دخول بالوصول الكامل لكل البيانات. لأن التطبيق مصمم للاستخدام الشخصي (مستخدم واحد)، هذا مقبول.
>
> **لو أردت دعم أكثر من مستخدم:** أضف عمود `user_id uuid DEFAULT auth.uid()` لكل جدول، ثم عدّل السياسات إلى:
> ```sql
> USING (auth.uid() = user_id)
> WITH CHECK (auth.uid() = user_id)
> ```

**توصيات إضافية:**
- استخدم كلمة مرور قوية لحساب Supabase.
- لا تشارك `service_role key` مع أي أحد.
- لا تشارك كلمة مرور حسابك في التطبيق.
- فعّل **Two-Factor Authentication** على حساب GitHub/Supabase إن أمكن.

## 🐛 حل المشاكل الشائعة

### 1) خطأ `permission denied for table ...`
**السبب**: صلاحيات الجداول غير ممنوحة لدور `authenticated`.
**الحل**:
```sql
GRANT SELECT, INSERT, UPDATE, DELETE
  ON ALL TABLES IN SCHEMA public
  TO authenticated;
```
أو أعد تشغيل `schema.sql` كاملًا — فهو يتضمن هذا تلقائيًا.

---

### 2) خطأ `relation "public.banks" does not exist`
**السبب**: لم يتم تشغيل `schema.sql` بعد، أو فشل جزئيًا.
**الحل**: افتح **SQL Editor** في Supabase، أعد تشغيل `schema.sql` كاملًا.

---

### 3) لا تصل رسالة تأكيد البريد
**الحل**:
- تحقق من مجلد الـ Spam.
- أو عطّل **Confirm email** من **Authentication → Providers → Email**.

---

### 4) التطبيق لا يتصل بـ Supabase
**تحقق من**:
- صحة **Project URL** (يبدأ بـ `https://` وينتهي بـ `.supabase.co`).
- صحة **anon key** (يبدأ بـ `eyJ`).
- أنك لم تخلط بين `anon` و `service_role`.

---

### 5) أسعار المعادن لا تُحدَّث
- تأكد من إدخال مفتاح GoldAPI في **الإعدادات**.
- تحقق من عدم استهلاك الحصة المجانية الشهرية.

---

### 6) تغييرات في `schema.sql` لا تنعكس على PostgREST
**الحل**: أضف في نهاية السكريبت:
```sql
NOTIFY pgrst, 'reload schema';
```
